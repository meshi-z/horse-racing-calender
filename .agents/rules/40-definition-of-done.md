# Definition of done

## Automated verification

変更内容に応じて、プロジェクトで定義された次の検証を実施する。

- lint
- 型検査
- 単体テスト
- 結合テスト
- E2Eテスト
- 本番ビルド
- アクセシビリティ自動検査
- Visual Regressionテスト

すべての変更で全項目が必要とは限らないが、省略した項目と理由を報告する。

## Data pipeline & Live verification (実通信検証)

スクレイパー、クローラー、出馬表APIクライアント等のデータ取得パイプラインを追加・修正した場合は、次を必ず実施する。

- **モック・フィクスチャ依存の禁止**: 単体テスト（Jest等）でモックやフィクスチャをパスさせるだけでなく、実通信を伴う検証を行うこと。
- **実機スモークテストの実行**: 対象の実サーバーと通信するコマンド（例: `npm run races:update-results -- --dry-run`、`npm run races:update-times -- --dry-run`）を最低1回実行し、実データが正しく取得・パースされることを検証する。
- **実通信検証結果の証跡確認**: 取得件数、取得されたレース名や勝ち馬名等のログが出力され、スタブや空データで終了していないことを確認する。

## Shadcn UI changes

Shadcn UIコンポーネントを追加または更新した場合は、次を確認する。

- CLIが変更した全ファイル
- 追加された依存関係
- ロックファイルの変更
- `components.json`の変更
- グローバルCSSとテーマトークンの変更
- 既存コンポーネントへの上書き
- ライトテーマとダークテーマ
- 既存利用箇所への影響

## Manual UI verification

UI変更では次を手動確認する。

- キーボードだけで主要操作を完了できる
- フォーカス表示が確認できる
- フォーカス順序が自然である
- Dialogなどを閉じた後に適切な位置へフォーカスが戻る
- 200%拡大で情報や操作が失われない
- 狭い画面で意図しない横スクロールが発生しない
- ライトテーマとダークテーマで内容を判別できる
- ローディング、空状態、エラー、無効状態が表示できる
- 長い日本語、英数字、エラーメッセージでレイアウトが崩れない
- エラー内容が色以外でも伝わる

## Completion report

完了報告には次を含める。

- 変更内容
- Shadcn UIコンポーネントの追加・変更内容
- 追加された依存関係
- 実行した検証と結果（データパイプライン変更時は、実通信スモークテストの実行ログ・取得件数・取得内容を含む）
- 実行できなかった検証（外部サイトのアクセス制限等で実通信ができなかった場合は、具体的なHTTPステータスや理由を明記）
- 既知の制約と残存リスク
