# Performance implementation rules

性能目標と計測条件は`docs/non-functional-requirements.md`を正本とする。

## Measurement

- 性能改善は推測ではなく計測結果に基づいて行う。
- 変更前後を同じデータ、環境、条件で計測する。
- 性能目標を満たさない場合は、計測値、条件、ボトルネック、残存リスクを報告する。

## Client performance

- Shadcn UIコンポーネントを追加するときは、同時に追加される依存関係とパンドルサイズを確認する。
- 利用しないコンポーネントや依存関係を追加しない。
- 大きなチャート、エディタ、日付処理、アニメーションのライブラリ追加は事前に影響を確認する。
- 不要なクライアントコンポーネント化を避ける。
- 不要な再レンダリングを避けるが、計測なしに過剰なメモ化を行わない。
- 画面外または初期表示に不要な重い機能は、必要に応じて遅延読み込みする。
- レイアウトシフトを発生させないよう、画像、Skeleton、非同期コンテンツの領域を確保する。

## Server and data access

- 既定のページサイズを持たない一覧取得を実装しない。
- リクエスト件数に比例して増加するN+1クエリを避ける。
- 必要な列とデータだけを取得する。
- キャッシュ導入時は、無効化条件、整合性、ユーザー間の分離を定義する。
- タイムアウト、キャンセル、失敗時の挙動を定義する。

## User experience

- 処理中であることが分かるフィードバックを提供する。
- 短時間の処理で不要なSkeletonやSpinnerを表示しない。
- 楽観的更新を使用する場合は、失敗時の復元方法を実装する。
- アニメーションによって操作可能になるまでの時間を遅らせない。
